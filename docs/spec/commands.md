# 脚本指令与内联标记规范

AA 剧本的"指令"分三类，写在不同地方，**不要混**：

| 类别 | 存在哪里 | 谁产生 | 例子 |
|---|---|---|---|
| ① 额外指令 | `ScriptData.additionalPrompt` 字符串 | 作者显式写（`[实]`）或由 AA 面板生成 | `#wait;2000`、`#bgshake` |
| ② 编译器自动指令 | `.aap` 里**没有**；AA 编译 `.aas` 时按字段推导 | AA 编译器 | `#N;m3`、`#N;hide`、`#nextepisode;…` |
| ③ 对话框内联标记 | `ScriptData.text` 字符串里 | 作者直接写进台词 | `[size=120]…[/size]`、`[FF0000]…[-]` |

证据等级：`[实]`=本次 36 个真实 `.aap` 统计；`[官]`=官方文档（`research/aa-docs/p17,p18`）；
`[三]`=HaloCue（`research/halocue/docs__commands.md`、`docs__format.md`、`tables.py`、`direction.md`）；
`[推]`=推测。

> **给 runtime 的一句话**：`.aap` 本身只存 ① 和 ③。
> ② 只在真 AA 编译出来的 `.aas` 里出现，复刻版如果直接解释 `.aap`，
> 需要**自己实现 ② 的推导规则**（本文第 3 节），否则走位/隐藏/进出场/自动停顿全都没有。

## 1. 语法总则

### 1.1 额外指令的语法

```
#指令名;参数1;参数2;参数3...
```

- `[官]` p17：「一条典型的指令由前缀（#）、指令名称和一定数量的参数组成」；
  「一个脚本内可以同时存在多个额外指令，用换行分割」。
- **指令分隔符 = 换行**（`\n`）。`;` 是**参数**分隔符，不是指令分隔符。
  `[实]` 证据：`additionalPrompt` 里出现 `"#wait;2000\n#hide…"`、`"#bgshake\n#wait;2000"`
  等写法；同一条指令内参数用 `;` 连写（`#zmc;instant;0,0;6400;`）。
- 严格格式（推荐实现）：
  1. 按 `\n` 切行（同时容忍 `\r\n`）；
  2. 每行 `trim()` 去掉首尾空白与 `\r`；空行忽略；
  3. 以 `#` 开头的行才是指令；行内按 `;` 切分；
  4. 第 0 段去掉 `#` 得到指令名（`wait`、`bgshake`、`zmc`、`st`、`stm`、`clearST`、
     `hidemenu`、`showmenu`、`fx`、`nextepisode`、`N;…`）；
  5. 参数按位置取；**末尾允许空参数**（`#zmc;instant;0,0;6400;` 的第 5 段是空串）；
  6. 数值参数用 `int()`/`float()` 解析，解析失败 → 忽略该指令并告警（不要崩）。
- 行内出现 `#` 但整行不是已知指令：忽略（前向兼容）。
- 大小写：`[推]` 指令名**区分大小写**（`clearST` 官方写法是驼峰）。
  `[实]` 样本里有一次 `#CLEARST`（大写，1 次）——不确认 AA 是否识别；
  **实现建议：指令名按 ASCII 严格匹配官方写法，但对已知指令的大小写变体宽容接受**，
  这样两种都能跑。
- 一条 `additionalPrompt` 里可以有多条指令，执行顺序 = 文本顺序（从上到下）。

### 1.2 参数坐标系（屏幕空间）

`[官]` p17：「屏幕中心即坐标原点 (0,0)，屏幕宽度固定为 **2960** 单位，高度可变。」

- 所有出现 `X,Y` 的指令（`#zmc`、`#st`、`#stm`）都用这套坐标：
  **原点在屏幕中心**，X 向右为正，Y 向上为正（`#stm;[0,-430]` 表示中心下方 430 单位，
  这是把文字放在对话框上方的常见写法 `[实]`）。
- 宽 2960 单位是逻辑单位，与实际分辨率无关；渲染时按 `屏幕宽/2960` 缩放。
- 高度可变（不同设备/窗口比不同）→ **Y 不要写死绝对位置**，官方也警告 `#st`/`#stm`
  的 Y 轴"因设备而异，会错位" `[三]`。
- `#zmc` 的「缩放系数」是**倒数**：实际放大倍数 = **3160 / 系数**
  （`[官]` p17/p18：`#zmc;instant;0,0;1000` → 放大 3.16 倍；
  系数 < 3160 放大，> 3160 缩小）。注意官方在这里用 **3160** 而不是 2960。
- `[实]` 实测参数范围：`#zmc` 的 X ∈ [−700, 500]，Y ∈ [−380, 500]；
  `#stm` 的 X 实测恒 0；`#st` 的 X 只出现 −1390/−1300/−1150/−1100/−900；
  字号 `#st/#stm` 实测 50–200，`#stm` 以 100 为主。

## 2. 额外指令（写进 `additionalPrompt`）完整表

### 2.1 `#wait;毫秒`

- 格式：`#wait;<毫秒数>`，例 `#wait;2000`。
- 作用：让**没有对话**（或对话已显示完）的脚本额外停留；`[官]` p17「使没有对话的脚本等待一段时间后再推进」。
- **关键语义：覆盖不是叠加** `[三]`（119/119 验证）。AA 会按第 4 节自动插默认 wait，
  作者写的 `#wait` 会**替换**那一行的默认值，而不是加在后面。
- 单位毫秒；官方建议 500 的倍数 `[官]` p18；`[实]` 出现 `#wait;0`（4 次，=照常立即推进）、
  `#wait;50`（126 次）、`#wait;888`（15 次）等非 500 倍数值，**必须原样接受**。
- `[实]` 使用量：`#wait;1000` 275、`#wait;2000` 260、`#wait;500` 143、
  `#wait;1500` 102、`#wait;3000` 50 等，是使用最多的额外指令。
- 边界：`#wait` 没有参数 → 忽略；负数/非数字 → 忽略。

### 2.2 `#bgshake`

- 格式：`#bgshake`（无参数）。背景抖一下。
- `[实]` 出现 5 次（36 工程）；`[三]` 在 139 工程里 14 次。想持续抖 → **连续多个脚本**各写
  `#bgshake` + `#wait;100` `[三]`。
- 实现：对背景层做短促随机位移（约 200–300ms），不改变背景图。

### 2.3 `#fx;效果名`

- 格式：`#fx;<效果名称>`。`[官]` p17/p18：**目前只支持 `AronaTouch`**（序章 ARONA 指纹识别特效）。
- 例：`#fx;AronaTouch`。
- `[实]` 36 工程中 **0 次**（没人用）；`[三]` 二进制里能找到 `AronaTouch` 字面量，
  但没找到对应 fx 动画类 → **未实测**，`[推]` 用不了就别用。
- 实现：可先做成"全屏 ARONA 触摸动效"占位；未知效果名忽略。

### 2.4 `#zmc;模式;X,Y;缩放系数;[持续时间]`

- 格式（`[官]` p17/p18 逐字）：
  ```
  #zmc;instant;X,Y;缩放系数;
  #zmc;smooth;X,Y;缩放系数;持续时间
  ```
- 参数：
  - `模式`：`instant`（瞬间变换，持续时间无效、可省略）/ `smooth`（平滑变换，**必须**有持续时间）。
  - `X,Y`：背景图的**中心点**要移动到屏幕上的坐标（屏幕中心原点，见 1.2）。
  - `缩放系数`：实际放大倍数 = `3160 / 系数`。
  - `持续时间`：`smooth` 模式下的毫秒数。
- 例：`#zmc;instant;300,-150;2160`、`#zmc;smooth;-650,-450;1860;500`。
- `[实]` 出现 44 次（HaloCue 139 工程口径）/ 本次 36 工程里 30+ 次；
  典型值：`#zmc;instant;0,0;6400;`、`#zmc;smooth;0,0;3160;2000`、`#zmc;instant;-200,-100;1800;1000`。
- 边界：
  - `smooth` 没有持续时间 → 忽略该指令（`[三]` 工具会警告）。
  - `instant` 结尾分号可省 `[官]`（例子里写 `…;1000;500` 说 500 无效可去掉）；
    但 `[实]` 样本普遍保留尾分号 → **实现时两种都接受**。
  - `[三]`：44 条 `#zmc` **没有一条**与 `#wait` 同脚本共现（默认 wait 已够），
    但社区文档说"后面必须跟 wait"——不必强制。
  - `[三]`：编辑模式切到下一个脚本会**恢复原样**；鉴赏模式会保持到换背景。
    复刻版按"状态持续到下次改变"实现更接近鉴赏模式。

### 2.5 `#st;[X,Y];模式;字体大小;` —— 屏幕文字（左对齐）

- 格式（`[官]` p17/p18）：
  ```
  #st;[X坐标,Y坐标];模式;字体大小;
  ```
  **结尾的英文分号不可省略**（少了整条失效 `[官]`）。
- 参数：
  - `X,Y`：文字**左端**的位置（屏幕中心原点）。
  - `模式`：`instant` 立即显示 / `smooth` 整体淡入 / `serial` 逐字打字机。
  - `字体大小`：**50 = 原大小** `[三]`（官方只说"字体大小"）。
- 文字内容从哪来：**屏幕文字与台词共用一个 `text` 字段**。
  `[官]` p18 的操作是「输入位置：Environment 额外指令栏；文字在对话框输入」——
  即：在 `additionalPrompt` 写 `#st;…`，同时把要显示的文字写进 `text`。
  该行通常没有角色/对话框（配合 `#hidemenu` 之类做无框演出）。
- `[实]` 出现 17 次（HaloCue 139 工程），`[实]` 本次样本：
  `#st;[-1400,-850];instant;50`（1 次）。
- 屏幕文字**不会自然消失**（预览模式也不消失）→ 用 `#clearST` 清除 `[官]`。

### 2.6 `#stm;[X,Y];模式;字体大小;` —— 屏幕文字（居中）

- 与 `#st` 完全相同，只是 `X,Y` 是文字**中心**。
- `[实]` 使用量远大于 `#st`：HaloCue 139 工程 23 次（serial 22 / instant 1）；
  本次 36 工程里 `#stm` 出现约 60 次（`#stm;[0,400];serial;125;`、
  `#stm;[-100,250];serial;100;` 等）。`[实]` `#stm` 的 X 恒为 0 的印象不成立
  （本次样本有 −100/250/1220 等），按通用坐标处理。
- 边界同上，结尾分号不可省。

### 2.7 `#clearST`

- 格式：`#clearST`（无参数）。清除**所有**屏幕文字。
- `[实]` 出现 20+ 次；`[官]` 提醒：屏幕文字不会自然消失，必须用它清。
- `[三]` 社区文档说这条指令有概率触发未知错误导致 AA 异常，退出项目重进可解——
  复刻版不必复刻这个 bug。
- 实现：清空屏幕文字层（不是清对话框）。

### 2.8 `#N;fx;{shot}` —— 角色中弹特效

- 格式：`#<栏位号>;fx;{shot}`，例 `#3;fx;{shot}`。
- `N` = **栏位号 1–5**，不能填 0；该位置必须有角色，否则无效 `[官]` p17/p18。
- `[实]` 出现 5 次（HaloCue 139）/ 本次 36 工程里 15 次；
  多行写法：`#1;fx;{shot}\n#3;fx;{shot}\n#5;fx;{shot}`（多个栏位同时中弹）。
- 注意大括号 `{shot}` 是字面量（不是模板）；`[实]` 36/36 如此。
- 已废弃/未见的写法：`#N;fx;shot`（无花括号）——不要生成，读取时可宽容。

### 2.9 `#hidemenu` / `#showmenu`

- 格式：无参数。隐藏/恢复**右上角菜单图标**。
- `[官]` p17/p18 有完整条目；`[实]` 本次 36 工程出现 `#hidemenu` 7 次、
  `#showmenu` 7 次（HaloCue 139 工程里 0 次，属"低频但真实存在"）。
- 只在鉴赏/预览模式看得到效果。
- 常与 `#wait` 连用：`#wait;3000\n#hidemenu`、`#wait;2000\n#showmenu` `[实]`。

### 2.10 `#nextepisode;<Header>;<Title>`

- 格式：`#nextepisode;<序号>;<标题>`，例 `#nextepisode;End;再见，再见！`。
- **这不是作者手写的指令**：AA 在编译时读取 `ExitNodeData.NeHeader` / `NeTitle`
  自动生成（`[三]` 3/3 验证）。所以 `.aap` 里 `additionalPrompt` 永远看不到它。
- 复刻版编译器/预览器的推导规则（如果 `IsEnding == false` 且 `NeHeader`/`NeTitle` 非空）：
  ```
  additionalPrompt += "\n#nextepisode;" + NeHeader + ";" + NeTitle
  ```
  分号数量：字段里本身可能含 `;`（`[实]` `NeScriptDirty.text` 出现 `"Kei;都是我的错……"`），
  所以**不要**把参数再拼接转义；原样用分号连接即可（`[推]`：AA 解析时取第 1、2 段）。
- 结局画面（`IsEnding == true`）用 `EndText`，多半不生成 nextepisode `[推]`。
- 显示效果：进入下一话的预告卡（"未完待续"）。

### 2.11 逃生舱 `#raw`（工具层概念，不是 AA 指令）

- HaloCue 允许作者写 `@raw #任意指令`，把它原样写进 `additionalPrompt` `[三]`。
- 复刻版编辑器如果做"高级指令原文"输入框，也应当允许任意 `#` 行直接落到
  `additionalPrompt`，不要白名单拦截（未知指令 AA 会忽略）。

## 3. 编译器自动生成的指令（`.aap` → `.aas` 时由 AA 推导）

`.aap` 里**不存**这些指令；它们由 AA 编译器按 `characters`、`placeText`、
`EntryNodeData`、`ExitNodeData` 等字段生成到 `.aas` 的命令流里。
复刻版直接解释 `.aap` 时必须自己实现下表，才能在预览里看到走位/隐藏/进出场。

> 证据等级：格式与生成条件来自 `[三]`（HaloCue 对 139 工程 + 19000 台词做
> `.aap`↔`.aas` 配对反推，命中率见每行）+ `[实]` 本次样本字段统计。
> **精确字节格式（分号/花括号）没有 `.aas` 样本可逐字节核对，标 `[三]` 的格式按
> HaloCue 文档转写；实现时对 `#N;m3` 与 `#N;m;3`、`#N;a` 与 `#N;A` 等变体宽容。**

| 指令 | 生成条件 | 含义 | 验证 |
|---|---|---|---|
| `#N;m<K>` | 本行 `startingPos != endingPos`（K = `endingPos`，**紧贴 m 后**） | 第 N 槽角色走位到 K 槽 | `[三]` 741/741 |
| （不发 m） | `startingPos == endingPos` | 原地不动 | `[三]` 27372/27372 |
| `#N;hide` | 上一行占着、本行为空的槽 | 该槽角色隐藏（切镜头） | `[三]` 1752/1756；`[三]` direction.md |
| `#N;<al\|ar\|a\|dl\|dr\|d>` | `appear != 0` | 进出场动画 | `[三]` 1852/1852 |
| `#N;jump` | `action == 6` | 跳（动作 6 是跳，不是气泡） | `[三]` docs__commands |
| `#N;em;<符号>` | `emoticon >= 0` | 表情符号气泡，如 `#N;em;[재잘]` | `[三]` |
| `#N;h` | `highlightedSlotNums` 含 N | 高亮第 N 槽 | `[三]` |
| `#N;closeup` | `shapeOverride` 含 4（特写位） | 立绘特写 | `[三]` |
| `#N;fx;{shot}` | 作者写（不是自动） | 中弹特效 | `[实]`/`[官]` |
| `#na;<文本>` | 旁白行（0 号槽说话 / 无立绘） | 旁白标记 | `[三]` docs__commands |
| `#title;<文本>` | 入口节点/标题行 | 标题卡 | `[三]` docs__commands |
| `#place;<文本>` | `placeText != ""` | 地点名称卡 | `[三]` docs__commands；`[实]` placeText |
| `#continued` | 接上一段（跨节点续接） | 续接标记 | `[三]` docs__commands |
| `#nextepisode;<H>;<T>` | 出口节点非 Ending 且有 NeHeader/NeTitle | 下回预告 | `[三]` 3/3 |
| `#all;hide` | 全场清空（换场/收尾） | 所有槽隐藏 | `[三]` direction.md（官方命令流） |
| `#wait;<ms>` | 见第 4 节自动等待 | 停顿 | `[三]` 98%/89% |

补充说明：

- `#N` 里的 **N 恒为数组下标**（9532/9532），不是"屏幕位置序号"。
- `#N;a` / `#N;d` 等与 `appear` 值一一对应：1=al、2=ar、3=a、4=dl、5=dr、6=d。
- `[推]` 若一行内既有走位又有进出场，AA 大概率先处理进出场再处理走位（否则新角色
  没有起始位置）；实现建议：**先 apply 进出场/隐藏，再 apply 走位，再其他指令**。
- `[实]` `.aap` 里 `additionalPrompt` 只存作者指令，**不会**包含上表自动指令——
  这也是复刻版"读 `.aap` 直接播放"时必须自己算的原因。

### 3.1 编译顺序（供复刻版实现"一行"的演出）

一行 ScriptData 的演出应当按下面的顺序求值（`[推]`，按状态依赖推导）：

```
1. 角色状态差异（来自 characters 数组 vs 上一行）：
   a. appear != 0  → 进出场（新角色就位）
   b. 本行为空而上一行有人的槽 → #N;hide（切镜头）
   c. startingPos != endingPos → 走位 #N;m<endingPos>
2. 表情/动作/立绘效果：faceId、emoticon、action、shapeOverride
3. 额外指令 additionalPrompt（按行顺序）：
   #wait / #bgshake / #zmc / #st / #stm / #clearST / #hidemenu / #showmenu / #N;fx;{shot} …
4. 环境状态更新：bgName（背景）、transition、bgEffect、bgmId、sound、popup、placeText
5. 显示 text（含内联标记、按字速）→ 玩家点击/自动 → 若没有覆盖，按自动等待落 duration
```

`[推]` 的依据：`#N;fx;{shot}` 必须知道 N 槽角色最终位置（所以角色状态先于额外指令）；
背景/音效要在台词出现前切换（否则第一帧文字盖在旧背景上）。**真机未见逐字节验证，
但按此顺序实现视觉差异最小。**

## 4. 默认自动等待（AA 会自动插 `#wait`）

`[三]` direction.md / tables.py（134 组 `.aap`↔`.aas` 配对实测）：

| 这一行有什么 | AA 自动插入 | 命中率 |
|---|---|---|
| 有表情符号（`emoticon >= 0`，且角色 name 非空） | `#wait;2500` | 4552/4643 = **98%** |
| 无气泡，但有走位 / 进出场 / 动作（`endingPos != startingPos` 或 `appear != 0` 或 `action != 0`） | `#wait;1500` | 1179/1331 = **89%** |
| 都没有 | 不插 | — |

规则：

1. 作者显式写的 `#wait` **覆盖**默认值（不是相加）`[三]` 119/119。
2. 一条 `additionalPrompt` 里有多条 `#wait` 时，用**最后一条**（`[推]`，无实测）。
3. 默认等待在**台词显示完之后**计时（文字打完+停顿，然后自动推进）。
4. `[实]` 本次 36 工程统计：`#wait;2000` 260 次、`#wait;1000` 275 次、
   `#wait;500` 143 次、`#wait;1500` 102 次；这些多为作者覆盖。
5. `[实]` 同一行同时有 `#wait` 与 `#bgshake` 的写法存在：
   `"#bgshake\n#wait;2000"`（顺序无关，两者都执行）。

> 给 preview/编辑器的建议：**不要**把自动 wait 写回 `additionalPrompt`。
> 它是编译器行为；写了等于覆盖，会让真 AA 的节奏和作者预期不一致。

## 5. 对话框内联标记（写在 `text` 里）

AA 的台词支持富文本标记。`[实]` 本次 36 工程 8268 条台词里含标记的有 61 条。

### 5.1 已验证在用的（官方文档 + 真实样本）

| 写法 | 效果 | 官方原文 | 样本用量 `[实]` |
|---|---|---|---|
| `[size=数字]文本[/size]` | 字号缩放；**60 = 原大小** | `[官]` p17/p18「文字放大」 | 有（含 `[size=120]`、`[size=200]` 等） |
| `[RRGGBB]文本[-]` | 变色，从 `[RRGGBB]` 开始染到 `[-]` 为止 | `[官]` p17/p18「文字颜色」；`[官]` 写的是 `[RRGGBBAA]…` | 有 |
| `[ruby=注音]文本[/ruby]` | 注音（注音部分不受变色影响） | `[官]` p17/p18「注音」 | 0（文档支持） |

颜色写法细节：

- 官方 p17 的格式是 `[RRGGBBAA]颜色文字[-]`，p18 例子是 `[FF0000]红色[-]`。
  即 **6 位 RGB 与 8 位 RGBA 都接受**；`[-]` 结束染色。
- 常用色：组织名淡蓝 `[7cd0ff]`、红 `[FF0000]`、青 `[00FFFF]`（`[三]`）。
- `[实]` 真实文本里还出现 `[ffb3ba]` 之类小写十六进制 → **颜色解析大小写不敏感**。

嵌套规则（`[三]` + `[官]`）：

- 正确：`[size=100][ruby=x]文本[/ruby][/size]`（size 在外层）。
- 反过来（size 在内）`[三]` 实测**只有 size 生效** → 实现建议：后开先闭的栈式解析，
  但尺寸/颜色要能独立叠加；若冲突，以"最后生效"为准。
- `[官]` p18：「对应的指令前缀后缀要对称放置」。
- 社区文档说嵌套最多 9 层；`[三]` 语料真实最大嵌套深度 **1**。
  实现支持到 8–16 层即可。

### 5.2 社区文档有、但未验证（不要默认支持 / 明确标未确认）

| 写法 | 效果 | 状态 |
|---|---|---|
| `[b]…[/b]` | 加粗 | `[三]` 139 工程 + 游戏二进制里 **0 次**，未确认 |
| `[i]…[/i]` | 斜体 | 同上 |
| `[u]…[/u]` | 下划线 | 同上 |
| `[s]…[/s]` | 删除线 | 同上 |
| `[sup]…[/sup]` | 上标 | 同上（与 sub 不兼容） |
| `[sub]…[/sub]` | 下标 | 同上（与 sup 不兼容） |
| `[两位数]文本` 或 `[a0]–[f9]` | 透明度（00 最透明） | 同上，0 次 |

兼容建议：解析到 **未确认标签**时，**原样保留标签文本**（不要删除、不要报错）；
如果实现富文本渲染，可忽略未知标签只显示内部文字。

### 5.3 内联标记与指令的边界

- 内联标记只影响**对话框文字渲染**，不影响剧情流程。
- 内联标记和额外指令可以出现在同一行：`additionalPrompt` 放 `#st`，`text` 放标记文本。
- `#st`/`#stm` 的屏幕文字也走 `text` 字段，因此**同样支持这些内联标记** `[推]`。
- 台词里的 `#` 不是指令（只有 `additionalPrompt` 里的 `#` 才是指令）。

## 7. 实现清单（照做即可）

### 7.1 Runtime 解释器

1. 解析 `additionalPrompt`：按第 1.1 节切成指令列表，缓存到 ScriptData 上。
2. 每行按第 3.1 节顺序求值：
   - `characters` 差异 → 走位/隐藏/进出场（`#N;m`/`#N;hide`/`#N;al..`）
   - `emoticon`/`action`/`shapeOverride` → 气泡/骨骼动画/shader
   - `additionalPrompt` → 背景抖动/缩放/屏幕文字/菜单/中弹
   - `bgName`/`transition`/`bgEffect`/`bgmId`/`sound`/`popup`/`placeText` → 环境
   - `text` → 富文本排版 + 字速显示
3. 打完字后：若 `additionalPrompt` 有 `#wait` 用其值；否则按第 4 节自动等待；
   都没有则等玩家点击。
4. `isDialogScript == false`（出口/演出节点）→ 不显示对话框，按指令与 `#wait` 推进。
5. 屏幕文字层独立于对话框，`#clearST` 清空；`#stm` 居中、`#st` 左对齐。
6. 坐标系：`screen_pos = screen_center + Vector2(x, y) * (viewport_width / 2960.0)`；
   `#zmc` 缩放倍数 = 3160 / factor。

### 7.2 编译器（`.aap` → 自研运行时数据）

1. 遍历节点图，从 Guid 全 0 入口开始。
2. 对每个 ScriptData 生成"事件序列"（可用 Godot Resource/Array[Dictionary]）：
   进出场 → 隐藏 → 走位 → 表情/动作/效果 → 额外指令 → 环境 → 台词 → 等待。
3. 出口节点：`IsEnding` → 显示 `EndText` 结局卡；否则生成 `#nextepisode;NeHeader;NeTitle` 预告。
4. 不要把自动 wait 写回 `.aap`（见第 4 节）；保存 `.aap` 时 `additionalPrompt` 原样写回。
